장비 소프트웨어 업그레이드 체계 구축 제안서

고객사별로 갈라진 장비 소프트웨어를 PRD를 고쳐 AI가 증분을 만들고, 가상 팹 시뮬레이터가 사무실에서 합격을 판정한 뒤 배포하는 체계로 바꿉니다. 누구도 해 보지 않은 일이므로 단계마다 한 가지를 증명하고 그 측정값으로 다음 단계로 넘어가는 8단계 로드맵으로 진행합니다. 핵심인 시뮬레이터와 판정 기준은 인텍플러스 엔지니어가 AI를 익혀 직접 만들고, 외부 주체는 도구와 방법을 제공합니다.

01 · 제안 요약

무엇을, 누가, 언제까지

문제

업그레이드 검증이 클린룸에서만 가능

고객사별로 소스가 다르고, 업그레이드 요청(검사기능 7 : 호스트 연동 3)마다 핵심 개발자가 직접 수정한 뒤 현장에서 확인합니다. 고객별 지식은 180명 중 20명 안팎의 핵심 개발자에게 몰려 있습니다.

해법

PRD → AI 증분 → 시뮬레이터 → 배포

자주 바뀌는 영역만 PRD로 관리하고, AI가 PRD 변경분만큼 코드를 만들며, 가상 팹 시뮬레이터가 사무실에서 합격을 판정합니다. 합격본만 고객 장비에 설치합니다.

수행 체계

내부 TF 8명 + 신규 장비팀 2명 + 외부 3주체 + PM

시뮬레이터·판정 기준·PRD 승인은 인텍플러스 TF가 맡습니다. bkit 저자는 공정 도구를, 브레인크루는 문서 입력을, AI 컨설턴트는 에이전트 설계와 교육을 맡습니다.

로드맵

증명 단위 8단계, 24개월, 2트랙

기존 장비 트랙은 판정 재현(단계 1) → 장비 재현(2) → AI 증분(3) → 실전 적용(5)으로, 신규 장비 트랙은 PRD부터 만들어 가상 팹에서 출하 전 검증(4)합니다. 단계 1은 4개월 차에 첫 성과를 보여 주고, 두 트랙은 확산(6)과 수렴(7)에서 합쳐집니다.

대표님께 요청드리는 결정은 세 가지입니다. ① 시뮬레이터 전담 엔지니어 2명과 핵심 개발자 3명의 시간(40~60%)을 TF로 확보, ② 파일럿 대상 선정(기존 고객 1곳과 신규 장비 1종)과 골든 이미지 사용 협의, ③ 외부 3주체(bkit 저자, 브레인크루, AI 컨설턴트)와의 계약 범위 승인입니다. 이 중 ①이 성패를 가장 크게 좌우합니다.

03 · 기술 타당성

역생성 PRD와 정확한 증분은 검증이 있어야 가능합니다

이 체계의 전제는 두 가지입니다. 고객별로 갈라진 현재 소스를 역으로 분석해 PRD로 만들 수 있어야 하고, PRD를 바꾸면 바뀐 만큼의 증분만 정확하게 만들어야 합니다. 결론은 가능하지만, AI가 정확하게 만드는 것이 아니라 정확한지를 기계적으로 검증할 수 있게 만드는 조건에서만 가능하다는 것입니다.

질문판단정확성을 확보하는 장치
① 고객별 소스를 역으로 PRD화할 수 있는가부분적으로 가능. 코드에 드러난 동작은 복원하지만, 설계 이유·타이밍·고객별 임시 수정은 놓치거나 틀릴 수 있음요구사항마다 근거 코드 위치와 신뢰도(확인됨·추정·빈칸) 표시. 시뮬레이터로 기록한 현재 동작과 대조해 맞는 것만 확정
② PRD를 바꾸면 증분만 정확히 만들 수 있는가조건부 가능. AI 생성은 같은 입력에도 결과가 조금씩 달라 그 자체로는 보장되지 않음요구사항 ID ↔ 코드 영역 추적표로 범위 밖 수정 차단, 새 합격 기준 통과(의도한 변경), 기존 회귀 시험 전부 통과(의도하지 않은 변경 없음), 예상보다 큰 diff는 사람 검토

역생성 난이도와 증분 정확도 (추정)

영역·변경 유형역생성 난이도증분 정확도 예상이유
판정 기준·레시피 값쉬움~보통매우 높음코드가 아니라 설정 diff라 사실상 결정적
GEM 보고 항목·이벤트쉬움높음코드 안의 표·상수로 존재, 구조화된 반복 패턴, 가상 호스트로 검증 쉬움
검사 항목 구성·물류 시퀀스보통보통~높음골든 이미지셋·L1 시뮬레이터 품질에 좌우
판정 알고리즘 세부·타이밍어려움낮음수치 처리의 미묘한 차이는 글로 옮기면 정보가 사라짐. 사람 주도(제품 PRD)

설계 시사점. 정확도를 가장 크게 올리는 방법은 AI 성능이 아니라 자주 바뀌는 영역을 설정·데이터 중심으로 바꾸는 것입니다. PRD 변경이 코드 생성이 아니라 설정 변경으로 끝날수록 결과는 결정적이 됩니다.

과거 업그레이드 재현 시험: 의견이 아니라 데이터로 판정

인텍플러스에는 정답지가 이미 있습니다. 과거 업그레이드 때 실제로 바뀐 소스가 버전 이력에 남아 있기 때문입니다. 단계 3(M5~M8)에서 4~6주 동안 아래 두 실험을 하고, 결과를 단계 3의 넘어가는 조건에 넣습니다.

실험 1 · 역생성 정확도

고객 1곳의 GEM 모듈과 검사 항목을 AI로 PRD화

핵심 개발자 검토와 시뮬레이터 동작 기록 대조. 측정: 개발자가 아는 동작 중 PRD에 담긴 비율, 틀린 기술 비율, 추정·빈칸 비율.

실험 2 · 증분 정확도

과거 업그레이드 5~10건을 AI로 재현

업그레이드 이전 소스와 PRD 변경분만 주고 생성한 증분을 실제 사람이 한 수정과 비교. 측정: 새 합격 기준 통과, 범위 밖 수정 0건, 회귀 0건, 리뷰 수정량, 반복 생성 시 편차.

한계. 검증은 시험이 덮는 범위까지만 증명합니다. 시험이 없는 동작의 변화는 잡지 못하므로 현장 최종 확인은 계속 필요합니다. 판정 기준 수치는 실험 전에 TF와 함께 정합니다. 실험 2는 고객별 소스의 과거 버전 이력이 업그레이드 단위로 남아 있어야 가능합니다.

근거. 역생성 명세에는 근거·신뢰도·빈칸을 붙여야 하며, 실행 검증 전까지 신뢰하지 않는다는 것이 최근 연구의 공통 결론입니다 (arXiv 2605.18684 Reversa, arXiv 2609.22719, 2026). 후자는 단일 기업 사례로 완전성은 검증되지 않았다고 스스로 밝힙니다.

04 · 장비와 데이터 전략

가상 팹을 만들기 위한 장비 이해와 데이터 전략

가상 팹은 장비가 무엇을 측정하고 무엇과 통신하는지를 그대로 흉내 내야 하므로, 출발점은 인텍플러스 장비 자체입니다. 아래는 인텍플러스 홈페이지의 연혁·제품 공식 사양(2026-10-09 확인)과 언론 보도를 바탕으로 정리한 장비의 흐름, 현재 라인업, 그리고 가상 팹에 필요한 데이터와 가상 팹이 새로 만드는 데이터입니다.

05 · 단계별 로드맵

누구도 해 보지 않은 일이라, 단계마다 증명하고 넘어갑니다

이 체계는 정해진 답이 없습니다. 그래서 시간 단위가 아니라 증명 단위로 단계를 나눴습니다. 원칙은 네 가지입니다.

  • 단계마다 한 가지만 증명합니다. 각 단계는 하나의 가설을 검증합니다.
  • 넘어가는 조건은 측정값입니다. 의견이 아니라 숫자로 다음 단계로 갑니다.
  • 실패해도 남는 자산이 있습니다. 다음 단계로 못 가도 그 단계의 산출물은 그대로 씁니다.
  • 막히면 범위를 줄여 다시 시도할 경로를 미리 정해 둡니다.

06 · 수행 원칙

외부는 도구와 방법을, 내부는 판단과 기준을

시뮬레이터의 핵심 업무는 검사 장비의 물리, 고객 공정, 고객 데이터를 모두 알아야 하므로 외부 인력이 대신할 수 없습니다. 또 이것은 인텍플러스가 앞으로 계속 쌓아 갈 기술 자산입니다. 그래서 외부 주체는 도구를 만들고, 방법을 가르치고, 옆에서 코칭하는 데까지만 맡고, 판단과 합격 기준은 인텍플러스 엔지니어가 소유합니다.

외부에 맡기지 않는 일이유담당
시뮬레이터 코어와 HAL 설계·구현장비 하드웨어 구조와 소스 전체를 알아야 하고, 장기 유지보수 대상인텍 시뮬레이터팀
골든 이미지셋 선정과 판정 기준무엇이 불량인지는 고객 공정과 검사 노하우의 핵심인텍 품질 + 핵심 개발자
변경 지도 확정AI가 손댈 범위를 정하는 안전 경계인텍 핵심 개발자
PRD 최종 승인, 배포 승인고객 장비에 대한 책임인텍 TF 리더
보안 등급 B·C 고객 데이터 직접 취급고객 보안 계약인텍 내부

AI로 일하는 방식으로 바꿉니다. 시뮬레이터 개발 자체도 인텍 엔지니어가 AI 코딩 도구로 합니다. 레거시 소스 분석, 가상 장치 코드, 시험 시나리오 생성에 AI를 쓰고, AI 컨설턴트는 매주 코칭합니다. 그래서 이 프로젝트의 결과물은 시스템과 함께 AI로 일할 줄 아는 내부 엔지니어입니다.

③ bkit 저자 (POPUP Studio)

M2~M8 집중 · 이후 운영 지원 · 4~7 MM

bkit을 인텍플러스 장비 소프트웨어용으로 포크·커스터마이징합니다. 공정(PRD → Plan → Design → Do → Check → Act → Report)과 합격 게이트를 만듭니다.

맡는 일

  • 장비용 PRD 템플릿 구현 (공통 PRD 상속, 변경 지도 구분, 기계 판독 사양, 합격 기준)
  • 문서 경로 구조: 공통·고객별 PRD
  • Check 단계에 시뮬레이터 결과 연동 (인텍이 정한 결과 규격을 읽어 일치율과 결합)
  • 가드레일 훅: PRD 제외 영역 수정 차단, PRD ID 없는 커밋 차단
  • 승인 게이트, 자동화 수준 조정
  • Report를 고객 제출용 추적표 양식으로
  • bkit 운영 교육 (Track B 일부)

산출물·일정

  • bkit-intek v1 (단계 3, M5~M6, 6~8주)
  • 시뮬레이터 연동·추적표 v2 (단계 3~4, M7~M8, 4~6주)
  • 운영 지원 월 2~4일 (M9~M24)
  • 인텍 저장소로 포크 이관, 운영 문서

하지 않는 일: 시뮬레이터 내부 구현, 고객 데이터 취급. 확인 필요: 참여 의사, 범위, 조건은 아직 협의 전입니다.

④ 브레인크루 (도구 + 엔지니어)

PoC 단계 3 · 신규 장비 GEM 입력 단계 4 · 망분리 단계 6 · 7~12 MM

고객 문서를 읽어 PRD의 입력을 만드는 앞단과, 사내 지식베이스를 맡습니다. 단계 3의 PoC 결과에 따라 구축 여부를 정합니다.

맡는 일

  • PoC: GEM 사양서 보고 항목 추출 정확도 100%, PRD 초안 품질, Git 변경 요청 연동, 망분리 내부 LLM 동작

  • 보안 등급 C 고객용 온프레미스 설치

산출물·일정
